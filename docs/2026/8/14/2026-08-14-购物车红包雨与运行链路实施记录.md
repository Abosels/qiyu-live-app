# 2026-08-14 购物车、红包雨与运行链路实施记录

本轮完成支付宝沙箱支付之前的待办：Maven 重复依赖清理、购物车前端接入、红包雨前端接入，以及红包相关服务的本地运行验证与阻断项定位。

- 两份 Nacos 示例 YAML 已同步真实数据库名、端口以及 RocketMQ `name-srv` 字段。

### 购物车前端

- 新增 `src/api/modules/shop.ts`，接入 SKU、购物车、数量变更、清空、预下单、订单支付接口。
- 新增直播间内的 `ShopCartPanel.vue`。

- 支付流程为：服务端预下单返回 `orderId` 和订单总价快照，前端仅提交 `orderId` 支付，不提交金额。

### 红包雨前端

- 新增 `src/api/modules/red-packet.ts`，接入直播间初始化、红包准备、红包广播、红包领取接口。
- 新增直播间内的 `RedPacketPanel.vue`。
- 主播端：先调用 `prepareRedPacket`，成功后再调用 `startRedPacket`。

- `useLivingRoomGiftEffect` 已将 `5564` 分发给红包面板，不影响原有送礼和 PK 消息处理。

### 红包消费者可观测性

## 未完成的运行验证

“向 `RECEIVE_RED_PACKET` 投递一条消息并由消费者确认消费”尚未完成，原因是本机 RocketMQ 环境存在历史 Docker 容器与 Compose 网络配置混用：

- 历史 `rmqnamesrv` 容器不受当前 Compose 管理，导致 Broker 重建时需要使用 `--no-deps`。
- Broker 最初向 NameServer 注册 Docker 内网地址 `172.18.0.3`，宿主机 Java 消费者无法回连。
- 已修正为 `brokerIP1=127.0.0.1`，并让 Compose 显式加载 `broker.conf`；但重建后 NameServer 路由尚未恢复，容器内 `mqadmin` 仍无法获得 topic 路由。
- gift-provider 后续还出现 Nacos 元数据映射注册失败，日志提示配置中心连接异常，导致完整服务启动不稳定。

因此本轮没有向真实红包业务投递有效消息，没有发生扣币、入账、红包金额弹出或数据库业务数据写入。

## 后续建议

在进入支付宝沙箱支付前，先独立整理本地 RocketMQ：停止并删除历史 `rmqnamesrv`、`rmqbroker` 容器后，统一使用 `D:\ProgramData_s\IT\rocketmq\docker-compose.yml` 启动 NameServer 和 Broker；确认 `mqadmin topicRoute` 返回 `127.0.0.1:10911` 后，再重启 gift-provider 并完成无资金非法消息验证，最后再执行真实红包领取测试。
