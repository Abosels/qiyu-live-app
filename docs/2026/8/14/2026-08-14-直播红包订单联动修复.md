# 2026-08-14 直播、红包与订单联动修复

## 本次范围

本次只完成直播列表接口契约、红包领取幂等与权限、订单超时回滚竞态三个阻断项，并同步前端直播列表调用。

未继续实现购物车页面、红包雨页面、支付宝沙箱支付和其他待办，作为后续独立小任务处理。

## 已修改内容

### 直播列表接口

- `LivingRoomController` 的直播列表接口改为接收 JSON 请求体。
- 修正原先反向的直播类型校验：现在要求请求体和 `type` 都存在。
- 限制页码为 `1` 到 `100`，避免无意义的大页码查询。
- 前端改为调用 `POST /living`，并按后端实际返回的 `list`、`hosNext` 读取数据。
- 前端展示字段映射为：`id -> roomId`、`roomName -> title`、`coverImg -> coverUrl`、`watchNum -> viewerCount`。

### 红包领取

- 修正创建红包时的主播权限判断。旧代码对 `Boolean` 使用非空判断，导致任意用户都可能通过；现在必须确认直播间主播等于当前用户。
- 修正主播进入直播间时红包配置码的空值判断，只有查到红包配置才写入响应。
- 新增“红包配置码 + 用户 ID”的 Redis 幂等键。
- 领取前先写入幂等键；同一用户重复领取直接返回已领取提示，不会再弹出金额。
- 资金扣减交易的 `bizId` 改为稳定值 `red-packet:{configCode}:{userId}`，使 RocketMQ 重投也能由资金流水幂等约束保护。
- 红包金额弹出后，如消息投递失败或发生异常，会将金额放回红包列表并删除幂等键，允许用户重试。

### 订单超时库存回滚

- 超时回滚前使用条件更新，将订单状态从 `PREPARE_PAY` 原子切换为 `CANCELLED`。
- 只有抢到上述状态转换的回滚任务才会回补库存。
- 支付流程已先将订单切换至 `PAYING`，因此回滚任务不会在支付处理中将订单取消并重复回补库存。
