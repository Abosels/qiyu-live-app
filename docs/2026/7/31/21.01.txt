三、存档点A — SendGiftMQ.uuId 审查

用户要求阅读 C:\Users\陈炎北\Downloads\SendGiftMQ-uuId来源与使用检查清单.md，
审查后确认两个核心问题：

1. 跨用户碰撞风险：
   - 当前 bizId = requestId（纯前端值），不同用户可能产生相同 requestId
   - 如果撞上了，t_qiyu_currency_trade 唯一索引 (biz_id, type) 会冲突
   - 方案：bizId = userId:requestId

2. 数据库字段长度：
   - 当前 biz_id VARCHAR(64)
   - userId(19) + ":"(1) + requestId(64) = 84 字符，超出 64
   - 需要 ALTER TABLE ... MODIFY COLUMN biz_id VARCHAR(128)

3. IM 重复广播：
   - MQ 重试时资金不重复扣（bank-provider 数据库幂等），
     但 IM 特效广播每次都会重复推送
   - IM 模块经排查确认：完全没有 msgId 去重机制
   - 采用方案 C：消费者侧 Redis 投递标记（gift-effect-sent:{uuId}）
     - IM 广播成功 → 设 key → 重试时跳过
     - IM 广播失败 → 不设 key → 抛异常 → MQ 重试 → 再次广播
     - at-least-once 语义，不会丢特效
     - 只改 SendGiftConsumer 一个文件，影响最小

五、风险评估
